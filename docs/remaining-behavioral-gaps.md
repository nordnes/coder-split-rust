# Remaining Behavioral Gaps

> **Scope:** Now that every Go route has a Rust counterpart (326/326, 100%),
> this document enumerates the remaining *behavioral* gaps — places where the
> Rust handler is reachable and returns a sane shape, but the underlying
> semantics still differ from the Go reference in `coder/`. It is the
> authoritative gap inventory; the per-route `crates/coder-server/PARITY_MATRIX.md`
> is a generated/older view that has drifted in places and should not be used
> to reason about what still needs work.

Categories are listed from most user-visible to most subsystem-specific, with a
priority matrix at the end.

These live under `/api/v2/workspaceproxies/me/*` and are called by each

matrix still marks them `stub-partial`. The remaining gaps are narrower.

| Route | Method | Current behavior | Real gap |
|-------|--------|------------------|----------|
| `/workspaceproxies/me/register` | POST | Enterprise-gated, authenticates the proxy token, validates fields, updates proxy registration, upserts the replica row, returns siblings + DERP mesh key (`crates/coder-server/src/handlers/workspaceproxies.rs:490`). | DERP mesh key is derived from `state.app_signing_key` rather than `GetDERPMeshKey`; `derp_force_websockets` is hardcoded `false`. |
| `/workspaceproxies/me/deregister` | POST | Enterprise-gated, authenticates, deletes the replica row (`crates/coder-server/src/handlers/workspaceproxies.rs:622`). | Does not emit replica-change pubsub events, so sibling proxies don't learn about the deregistration in real time. |
| `/workspaceproxies/me/coordinate` | GET | Enterprise-gated, authenticates, upgrades to WebSocket, runs a ping/pong keepalive and logs inbound frames (`crates/coder-server/src/handlers/workspaceproxies.rs:667`). | No actual multi-agent tailnet coordination — the Go handler bridges the proxy into the coordinator so agent tunnels can egress via the proxy. | `/workspaceproxies/me/crypto-keys` | GET | Enterprise-gated, authenticates, validates the `feature` param against a whitelist, returns active keys, lazy-generates a 32-byte key if none exists (`crates/coder-server/src/handlers/workspaceproxies.rs:716`). | No rotation/expiry/retirement scheduler — keys are created once and never rotated. |

## 5. OAuth2 Behavioral Gaps (2)

The OAuth2 provider flow is now largely implemented (PR #193), but two
items remain short of Go parity.

1. **Token revocation shape (`POST /oauth2/revoke`)** — the Rust handler in
   `crates/coder-server/src/handlers/oauth2.rs:1166` correctly follows RFC 7009
   (returning 200 even for unknown tokens) and tries both access- and
   refresh-token lookups, but it only deletes the token row. The Go
   implementation also cascades to dependent session tokens created from the
   OAuth2 token and emits an `audit_logs` entry per revocation.

2. **Dynamic Client Registration (RFC 7592) edge cases** — `post_oauth2_register`,
   `get_oauth2_client`, `put_oauth2_client`, `delete_oauth2_client` are complete,
   but the Rust code hashes the registration access token in best-effort fashion
   and returns 401 on lookup failure; the Go implementation has stronger
   replay protection (salted HMAC per client) and enforces the
   `software_id` + `software_version` redirect URI lock-step updates. Low
   priority unless external RFC 7592 clients are in scope.

## 6. Agent RPC Protocol Gap

This is the single largest subsystem gap in the backend. Go exposes the
agent↔coderd RPC surface as DRPC (Gogo-protobuf services) carried on a
yamux-framed WebSocket at `/api/v2/workspaceagents/me/rpc`. Rust upgrades
the same endpoint to a WebSocket and uses **JSON text messages** with a
custom message-type discriminator.

See `handle_agent_message` at `crates/coder-server/src/handlers/agents.rs:1901`
and `handle_agent_rpc_socket` at `crates/coder-server/src/handlers/agents.rs:1811`.

### Handled message types (5)

- `report_listening_ports` — updates `AgentProvider` port cache
- `report_stats` — inserts into `workspace_agent_stats`, replies with report interval
- `report_lifecycle` — persists lifecycle state + publishes pubsub event
- `update_metadata` — upserts metadata rows + publishes pubsub event
- `push_logs` — appends to `workspace_agent_logs` + publishes pubsub event

### Unhandled message types

At minimum the following DRPC RPCs on the Go `AgentAPI` are not handled
and fall through to the `_ => { debug!("unknown agent message type"); None }`
branch:

1. `get_manifest` / `GetManifest` — agent asks for its workspace manifest
   (env vars, scripts, apps, DERP map, tailnet keys). Without this a Go agent
   cannot configure itself on connect.
2. `get_announcement_banners` / `GetAnnouncementBanners` — agent polls for
   announcement banners to display in the terminal greeting.
3. `update_startup` / `UpdateStartup` — agent reports the result of its
   startup script, including expanded dirs and tailnet node preferences.
4. `batch_update_app_health` / `BatchUpdateAppHealth` — agent reports
   workspace-app health-check outcomes, which feed the workspace-status UI.

### Transport gap

Beyond the missing RPCs, the outer framing is different:

- No yamux multiplexing (Go uses one WS carrying many concurrent streams).
- No DRPC header/response envelope — replies are ad-hoc JSON objects
  (`{"type": "stats_response", "report_interval": 10}`).
- Outbound server→agent commands are plain text JSON on the same socket
  rather than DRPC replies keyed to a request stream ID.

A Go-compiled agent therefore cannot currently speak to a Rust coderd. This
is the blocker for running real provisioned workspaces end-to-end.

## 7. Provisioner / Template Gaps (2)

1. **Provisioner tag matching** — `app.rs:2068` uses
   `json_tags_contained_by(job.tags, input.provisioner_tags)` to pick
   eligible daemons, and all callers that create jobs currently pass
   `provisioner_tags: json!({})` (empty). The Go side uses a richer
   `ProvisionerTagSet` with wildcard (`*`) matching and scope tags
   (`scope: organization` vs `scope: user`). Until jobs are created with
   meaningful tags, non-default provisioners will not be reachable.
2. **Template dynamic-parameter evaluation** — see §3; the handler
   returns stored parameter definitions rather than driving the
   provisioner's Plan phase. This is adequate for templates that only use
   static parameters but wrong for any template that uses conditional
   `option` or `validation` blocks.

## 8. Workspace Quota Stub (1)

`compute_workspace_quota` in `crates/coder-server/src/handlers/quotas.rs:62`
always returns `{credits_consumed: 0, budget: -1}` (unlimited). The TODO
comment correctly identifies the missing pieces:

- `state.entitlements` is not yet checked for `FeatureName::TemplateRbac`
- the real queries (`get_quota_allowance_for_user`,
  `get_quota_consumed_for_user`) exist in `coder-db` but are not called.

Net effect: enterprise deployments that license `template_rbac` cannot
enforce quotas via the Rust backend; both the deprecated
`/workspace-quota/{user}` and the organization-scoped
`/organizations/{organization}/members/{user}/workspace-quota` are
affected.

## 9. Notification Dispatch Gaps (2)

The notification dispatch loop (`coder-notifications/src/lib.rs:119`)
correctly dequeues pending messages, dispatches per-method, and
increments the attempt counter / marks permanent failure. Two gaps
remain.

1. **SMTP email dispatch is a stub** —
   `coder-notifications/src/lib.rs:171` returns
   `NotificationDispatchError::Transport("SMTP email dispatch is not yet
   implemented".to_owned())` even when SMTP host is configured. Messages
   queued with `method=email` always retry and eventually land in
   `PermanentFailure`. Needs a `lettre`-backed sender.
2. **Webpush transport does not retry on transient failures** — the
   webhook path calls `http_client.post(...)` once, treats any non-2xx
   as a transport failure, and increments the attempt counter. Go
   distinguishes between retriable (5xx, timeouts) and terminal (4xx)
   failures and backs off exponentially; Rust uses a constant poll
   interval.

Inbox dispatch (`method=inbox`) and the webpush VAPID signing path are
complete.
